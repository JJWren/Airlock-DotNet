# U3 Infrastructure — NFR Requirements

**Stage**: CONSTRUCTION — U3 Infrastructure — NFR Requirements (Standard depth)

Only what is specific to `Airlock.Infrastructure`; system-wide NFRs stay in `inception/requirements/requirements.md`,
and the constraints U2 handed to U3 (`u2-application/code/code-generation-summary.md`) are requirements here. Values
marked "NFR Design" are chosen in the next stage within the bounds given.

| ID | Quality | Requirement | Check | Trace |
|---|---|---|---|---|
| U3-NFR-01 | Dependencies | `Airlock.Infrastructure` references `Airlock.Application`, `Airlock.Domain` and adapter packages only — HTTP and resilience, QuestPDF, configuration binding — never `Airlock.Web` or ASP.NET Core. The eight ports are implemented here and only here. | Architecture rules 3 and 4, each with a positive control | NFR-02; IR-26 |
| U3-NFR-02 | NVD resilience | 429, 403, 5xx, timeouts and network errors are retried with exponential backoff and jitter, honouring a usable `Retry-After` and using an own minimum when it is 0. Each attempt has a timeout, and each lookup — every page, attempt and backoff included — ends within 2 minutes, answered or `CatalogFailed`. | Tests on a fake HTTP handler and a fake clock: retry counts, delays, the minimum after `Retry-After: 0`, the attempt timeout and the 2-minute bound | NFR-04; IR-08; S0 N9; U2-NFR-05 |
| U3-NFR-03 | Rate limit | Every NVD request, retries included, passes one application-wide limiter that starts requests at least `Nvd:Window` / `Nvd:RequestsPerWindow` apart (600 ms), so no 30-second span holds more than 50 requests and waits stay short. A request waits for its turn rather than failing, leaves the queue at once when its lookup is cancelled, and its wait counts towards the lookup's 2 minutes. | On a fake clock, 16 callers with injected 429s: starts at least 600 ms apart and no 30-second span over 50 (defect 9); a cancelled waiter leaves without taking a turn | NFR-04; IR-07; defect 9 |
| U3-NFR-04 | Process control | A Syft run ends — its whole process tree killed and gone — within 1 second of cancellation or of `Timeouts.SyftRun`, on Windows and Linux, so the Application records the final status in time (U2-NFR-04). Syft is started without a shell, with its arguments as a list. Only the last 4 KB of its error output are kept. | A stand-in process with a child of its own: both gone within 1 second of cancellation and of the time limit; the real Syft in the integration tests | FR-16; NFR-06; IR-01, IR-02; U2-NFR-04; defect 3 |
| U3-NFR-05 | Large inputs | Uploads are copied to disk in fixed-size buffers and never held whole in memory, up to `Limits.MaxBytesPerScan` (2 GiB). Syft's JSON and NVD's responses are parsed as they stream in. Reading a `.nupkg` opens only its `.nuspec` entry and reads at most 1 MB of it. | A generated 256 MiB upload is staged with under 16 MB allocated; a `.nuspec` that expands past 1 MB counts as unreadable (IR-04) | NFR-05; FR-02; IR-04, IR-12 |
| U3-NFR-06 | Portability | The same behaviour on Windows (development) and Linux (container): the process-tree kill, the host path rules (IR-19), Syft's file name (`syft.exe` on Windows, IR-06), deletion retried while Windows still locks a file (IR-13) and owner-only staging folders on Linux (IR-11). The install scripts run on Windows PowerShell 5.1 and PowerShell 7, and on POSIX shells for Linux and macOS. | Unit tests on Windows and Linux in CI from U6; integration tests on both, Linux in the container | NFR-06; IR-25 |
| U3-NFR-07 | Security | The NVD key appears only in the `apiKey` header — never in a URL, a log line, an exception message, a health detail or Syft's environment; HTTP client logging redacts every header. Staged files never land outside their scan's folder. NVD is reached over HTTPS only. External text is cleaned before it is logged (U2 AR-25), and a value the Domain rejects fails the whole Syft output or NVD lookup rather than being trimmed (IR-03, IR-09). The install scripts download over HTTPS and place Syft only after its SHA-256 checksum matches. | A full lookup logged at Trace in every category holds no key; Syft's environment holds no key; staging refuses a path that escapes; options refuse an `http` base URL | NFR-03; E13; IR-12, IR-22 to IR-25; defect 5 |
| U3-NFR-08 | Observability | Each Syft run logs its input, duration and outcome; each NVD request its kind, status, attempt and duration — never the key or a whole response body. The adapters' categories (`Airlock.Infrastructure.*`) reach the Live Log like the Application's, and Live Log entries carry the formatted message only, never exception details. | Tests on a fake logger assert the lines, their levels and the absence of secrets | NFR-07; FR-18; IR-15 |
| U3-NFR-09 | Live Log | Publishing an entry takes time in proportion to the number of subscribers and never waits. Every subscriber receives every entry its 1,000-entry buffer can hold, and a new one first receives the last 200. | Two subscribers receive every line (defect 4); a subscriber that never reads slows neither the others nor the publisher | FR-18; IR-17; Q-U3-1; defect 4 |
| U3-NFR-10 | Performance | Reading and mapping a 2,000-record NVD page takes under 1 second; parsing Syft's 281-package output (S0 S10, about 290 KB) under 100 ms and a generated 10,000-package output under 2 seconds; rendering a 500-finding report under 5 seconds. | Measured in Build and Test (performance instructions), with generous bounds asserted in the unit tests | NFR-05 |
| U3-NFR-11 | Startup | Options are validated at startup, and an invalid one stops it with a message naming the option (IR-22). A missing NVD key or Syft binary does not: Airlock starts DEGRADED. The QuestPDF licence is set once. Syft's status is checked on first use and then cached (IR-05), so startup never waits for Syft. | Composition test: valid options start; each invalid one stops startup naming it; no key and no Syft still start | FR-23; E13; IR-05, IR-21, IR-22 |
| U3-NFR-12 | Testability | No unit test needs the network or Syft: NVD answers come from the recorded S0 responses through a fake HTTP handler, Syft outputs from the recorded S0 files. Tests that run the real Syft carry `Category=Integration` and are skipped when it is absent. | The unit suite passes with the network off and no Syft installed | NFR-09 |
| U3-NFR-13 | Coverage | Every rule IR-01 to IR-26 has its check in the rule-to-test map. Coverage of `Airlock.Infrastructure` is at least 85 % of lines and 80 % of branches, measured with the integration tests included (Syft present, as CI will have it from U6). | Coverage report from `dotnet test`; enforced in CI from U6 | NFR-09 |
| U3-NFR-14 | Maintainability | Names follow GLOSSARY.md; each rule's implementation carries a one-line comment naming its IR id; adapters stay thin, with parsing and mapping in their own internal classes (`SyftJsonParser`, `NuspecReader`, `NvdResponseMapper`); warnings are errors. | Build | NFR-08 |
