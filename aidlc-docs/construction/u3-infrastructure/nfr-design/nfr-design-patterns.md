# U3 Infrastructure — NFR Design Patterns

**Stage**: CONSTRUCTION — U3 Infrastructure — NFR Design (Standard depth)

| NFR | Pattern | How it is applied |
|---|---|---|
| U3-NFR-01 Dependencies | Adapter packages only, guarded by tests | `Airlock.Infrastructure.csproj` references `Airlock.Application`, `Airlock.Domain` and these packages: `Microsoft.Extensions.Http`, `Polly.Core`, `Polly.RateLimiting`, `QuestPDF`, `Microsoft.Extensions.Logging` (the Live Log provider's filter rules), `Microsoft.Extensions.Options.ConfigurationExtensions`, `Microsoft.Extensions.Configuration.Binder` and `Microsoft.Extensions.Hosting.Abstractions` (the staging sweep). Architecture rule 3 checks that the assembly references no `Airlock.Web` or `Microsoft.AspNetCore` assembly and that no Infrastructure type depends on those namespaces. Rule 4 checks that each of the eight port interfaces has exactly one implementation, and that it lives in `Airlock.Infrastructure`. The public types are the port implementations (the staging area itself stays internal), the options classes and the two registration classes; everything else is internal. |
| U3-NFR-02 NVD resilience | A Polly pipeline around each whole page, inside a lookup deadline | `NvdApiClient` runs every page request through one `ResiliencePipeline<NvdAttempt>` built on the injected `TimeProvider`, outermost first: the retry, the pacer (U3-NFR-03), a 30-second attempt timeout. An attempt sends the request with `ResponseHeadersRead`, then reads and parses the body inside the attempt, so the timeout and the retries cover the whole answer. For statuses an attempt returns a result instead of throwing: a page; not found (404); retryable (403, 429 and 5xx, with any `Retry-After`); or failed (any other status, or a body that is not NVD JSON, which is never retried). The retry handles retryable results, `HttpRequestException`, `IOException` and the attempt timeout, for at most 5 attempts. Its delay is a usable `Retry-After` of 1 to 60 seconds when NVD sends one, otherwise 2 seconds doubling up to 30, with ±20 % jitter from an injectable random source, so `Retry-After: 0` waits at least 1.6 seconds (S0 N9). The catalog wraps each lookup, every page included, in a 2-minute `CancellationTokenSource` on the `TimeProvider`, linked to the scan's token. When the deadline ends a lookup the answer is `CatalogFailed("NVD did not answer in time")`; when the scan's token ends it, the cancellation propagates. Worst cases for U2-NFR-05: an NVD that refuses at once fails a lookup after about 30 seconds of retrying and ends a scan in about a minute; an NVD that never answers fails each lookup at the deadline and ends a scan in about 4 minutes. |
| U3-NFR-03 Rate limit | One pacer for the whole application | `NvdRequestPacer` is a `RateLimiter` (System.Threading.RateLimiting), registered once, that the pipeline consults between the retry and the attempt timeout. Every attempt takes a turn, and the wait for a turn is not part of the attempt's 30 seconds. Waiters queue on a `SemaphoreSlim` in arrival order. The one at the front waits on the `TimeProvider` until `Nvd:Window` / `Nvd:RequestsPerWindow` (600 ms) has passed since the last start, records its start and lets the next one in; a timer can end up to a millisecond early, so the spacing is checked again after each wait. A waiter cancelled in the queue or during its wait leaves without recording a start, and the pacer never refuses a request. With 4 lookups in flight a request waits at most about 2.4 seconds (with 16, about 9.6), well inside the lookup's 2 minutes. |
| U3-NFR-04 Process control | A runner that owns the process from start to exit | `SyftProcessRunner` starts the binary with `ArgumentList`, `UseShellExecute = false` and `CreateNoWindow`, closing standard input at once. Its environment is a copy of Airlock's with `SYFT_CHECK_FOR_APP_UPDATE=false`; with `TMPDIR`, `TMP` and `TEMP` pointing at the run's own temporary folder; and with the NVD key removed, by name (`NVD_API_KEY`, `Airlock__Nvd__ApiKey`) and by value. Standard output goes to the caller's reader as a stream while standard error is read alongside into a 4 KB tail; when the reader stops early, the rest of the output is drained so Syft never blocks on a full pipe, and the exit code decides the outcome (IR-02). The run's limit is a `CancellationTokenSource(Timeouts.SyftRun, TimeProvider)` linked to the scan's token. When either fires, the runner calls `Process.Kill(entireProcessTree: true)` and waits up to 5 seconds for the exit, then answers `SyftTimedOut` for the limit or throws `OperationCanceledException` for the scan. A binary that cannot be started is `SyftFailed` ("Syft could not be started: …"). The temporary folder is deleted after the run like a staging folder (U3-NFR-06), so a killed Syft leaves nothing behind. |
| U3-NFR-05 Large inputs | Streams end to end, with a cap on everything read whole | Uploads are copied through one 80 KiB buffer from `ArrayPool<byte>.Shared` into a `FileStream` opened with `CreateNew` and `FileOptions.Asynchronous`, counting bytes. Once the count passes the bytes left, the partial file and its folder are deleted and the answer is `ArtifactTooLarge`. Syft's and NVD's JSON go through `JsonSerializer.DeserializeAsync` over the stream, with source-generated contexts that declare only the fields Airlock reads (`domain-entities.md`), so every other field is skipped rather than built. NVD answers are requested compressed (gzip or Brotli). Before a NuGet package's directory is loaded, its end record must announce at most 65,534 entries (65,535 means ZIP64). The `.nuspec` at the root is read through a stream that stops at 1 MB, and a package past either cap counts as having an unreadable `.nuspec` (IR-04). |
| U3-NFR-06 Portability | One code path, with the operating system chosen at the edges | `Process.Kill(entireProcessTree: true)` on both systems. Syft's file name is `syft.exe` on Windows and `syft` elsewhere, both in the search and for a configured folder (IR-06). `HostFileSystem` compares paths ignoring case on Windows and macOS (IR-19). On Linux and macOS, folders are created with `UnixFileMode` 0700 and files with `FileStreamOptions.UnixCreateMode` 0600; on Windows they inherit the access of the user's temporary folder. Deletion is `Directory.Delete(recursive: true)`. On failure, every file and folder in the tree is made writable by its owner — the read-only attribute on Windows; owner write and execute on folders elsewhere, since archives Syft unpacks can carry read-only modes — and when that changed anything, the deletion is tried again at once. A file still locked is waited for instead, 100, 200, 400 and 800 ms on the `TimeProvider`, within 5 attempts. The install scripts are PowerShell that runs on 5.1 (TLS 1.2 set explicitly, `Invoke-WebRequest -UseBasicParsing`) and on 7, and POSIX `sh` with `set -eu`, `uname` for the system and architecture, and `sha256sum` or `shasum -a 256`. |
| U3-NFR-07 Security | The key in one place; untrusted input parsed defensively | The key is read from `NvdOptions` and added to each request as the `apiKey` header, nowhere else. The HTTP client factory's own logging is off for the NVD client (`RemoveAllLoggers`): its formatted messages redact headers, but the structured state it hands every provider holds the raw values. Headers stay redacted (`RedactLoggedHeaders(_ => true)`) for any logger added later, and none of Airlock's log methods takes the key or a request as an argument. Exception text from HTTP is cleaned (U2 AR-25) and holds no headers. The health detail says only whether a key is configured, and Syft's environment loses the key (U3-NFR-04). A staged file's resolved path must lie inside the area's folder, compared on full paths segment by segment (IR-12). The options refuse a base URL that is not an absolute `https` URL (IR-22). XML is read with `DtdProcessing.Prohibit` and no resolver, within the caps of U3-NFR-05. Values from Syft and NVD reach the Domain as they are, and a rejection fails the run or the lookup (IR-03, IR-09). The install scripts download over HTTPS only and compare the checksum from the release's checksums file before anything is extracted. They extract into a temporary folder and move the binary into `bin/` at the end; nothing is piped into a shell. |
| U3-NFR-08 Observability | A source-generated catalogue per adapter, in Airlock categories | `[LoggerMessage]` methods with stable event ids — 2100s Syft, 2200s NVD, 2300s staging, 2500s reports and configuration — in the style of U2's catalogue. Each NVD request is logged at Trace with its kind, page, status, attempt and duration: the Application already logs each lookup at Debug, so the Terminal does not show every request twice. Retries, malformed CPEs (404), a killed Syft and a staging folder still locked are Warnings. A Syft run's end (input, duration, exit code) and a lookup's final failure are Debug lines, because the Application reports the outcome. Every category is the class's full name under `Airlock.Infrastructure`, so the Live Log captures it. |
| U3-NFR-09 Live Log | One lock, a replay ring and a channel per subscriber | `LiveLogBroadcaster` keeps a ring of the last 200 entries and an array of subscribers behind one `System.Threading.Lock`. Each subscriber is a bounded `Channel` of 1,000 entries with `DropOldest` and a single reader. Subscribing takes the lock, writes the ring into the new channel and adds the channel, so no entry is missed or repeated between replay and live; leaving removes it. Publishing takes the lock, adds the entry to the ring and calls `TryWrite` on each channel, which never waits. `LiveLogLoggerProvider` implements `ISupportExternalScope` to read the `ScanId` scope entry (the innermost wins). It keeps the formatted message only, never the exception, publishes the entry, then hands a scan-scoped entry to `ScanLogRouter`. Its own filter rules (`Airlock` at Debug, every other category off) outrank the general rules, so `LOG_LEVEL` moves only the console (IR-18). A thread-static guard drops any entry logged while the provider is publishing, so no future log call on that path can recurse. |
| U3-NFR-10 Performance | Parse once, map once | Source-generated JSON contexts, without reflection. Mapping is one pass per page or output, with the Domain's constructors as the only validation, and NVD descriptions are cut to 16,384 characters as they are mapped (IR-09). The PDF is composed in one pass from the scan, and QuestPDF does the paging. The unit tests assert bounds ten times the targets; Build and Test measures the targets themselves. |
| U3-NFR-11 Startup | Validate on start, probe on demand | The options bind from `Airlock:Nvd`, `Airlock:Syft` and `Airlock:Staging` with `ValidateOnStart` and one `IValidateOptions<T>` per class, in the Application's message form ("Airlock:Nvd:Window must be between 1 second and 1 hour"). A missing or blank key leaves `IsConfigured` false. `AddAirlockInfrastructure` sets QuestPDF's licence to Community. The first `GetStatusAsync` runs `syft version` (10-second limit) and caches the answer for `Syft:StatusCacheDuration`; concurrent callers share one probe, and a caller's cancellation ends its own wait, not the probe. `AddAirlockEnvironmentVariables` translates `LOG_LEVEL`: the original's names (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`) and .NET's level names, in any case. Any other value stops startup, naming `LOG_LEVEL`. |
| U3-NFR-12 Testability | Recorded answers, a fake clock and a stand-in for Syft | `FakeNvdHandler`, an `HttpMessageHandler`, answers from the recorded S0 responses by query. It can delay, fail or answer a sequence of statuses, and it records every request with its time on the fake clock. `FakeTimeProvider` drives the pacer, the retries, both timeouts, the Syft limit and the deletion retries. `Airlock.Infrastructure.StandIn`, a small console program in `tests/`, plays Syft for the runner: it writes a given file to standard output, fills standard error, exits with a given code, hangs, or starts a child of itself and prints the child's process id. Real-Syft tests carry `[Trait("Category", "Integration")]` and call `Assert.SkipUnless` when the IR-06 search finds no Syft. |
| U3-NFR-13 Coverage | The rule-to-test map, plus the checks in `logical-components.md` | Test classes follow the map in `business-logic-model.md`. Coverage comes from `dotnet test --coverage --coverage-output-format cobertura`, with Syft installed by the install script so the integration tests count. |
| U3-NFR-14 Maintainability | Namespaces by adapter; rule ids in comments | Namespaces as in `logical-components.md`. Each rule's code carries a one-line `// IR-nn` comment, and public types have one-line XML summaries. Parsing and mapping stay in `SyftJsonParser`, `NuspecReader` and `NvdResponseMapper`. |

## Values chosen

| Setting | Default | Allowed | Reason |
|---|---|---|---|
| `Airlock:Nvd:RequestsPerWindow` | 50 | 1 to 1,000 | NVD's keyed limit; lower it if Build and Test sees 429s |
| `Airlock:Nvd:Window` | 30 seconds | 1 second to 1 hour | NVD's rolling window |
| `Airlock:Nvd:BaseUrl` | `https://services.nvd.nist.gov/rest/json/cves/2.0` | an absolute `https` URL | IR-22 |
| `Airlock:Nvd:ApiKey` | none | any; blank counts as none | IR-22: without one, Airlock starts DEGRADED |
| `Airlock:Syft:BinaryPath` | none: the IR-06 search | not blank when given | IR-06 |
| `Airlock:Syft:StatusCacheDuration` | 30 seconds | 1 second to 1 hour | The UI asks for health about every 10 seconds, so `syft version` runs at most twice a minute, and a Syft installed while Airlock runs shows within half a minute |
| `Airlock:Staging:Root` | `<system temp>/airlock-staging` | a full path | IR-11; a relative path would depend on the working directory |

| Fixed value | Size | Reason |
|---|---|---|
| Pacing interval | `Nvd:Window` / `Nvd:RequestsPerWindow`: 600 ms | U3-NFR-03 |
| NVD attempts | 5 | About 30 seconds of retrying rides out a short throttle; the outage breaker handles longer outages |
| Backoff | 2 seconds doubling up to 30, ±20 % jitter | U3-NFR-02; the first retry waits at least 1.6 seconds |
| `Retry-After` honoured | 1 to 60 seconds | S0 N9: 0 is no usable delay |
| Attempt timeout | 30 seconds | Long enough for a full page from a slow NVD; the lookup deadline still ends a lookup whose attempts keep timing out |
| Lookup deadline | 2 minutes | U2's constraint |
| Page size | 2,000 records | NVD's maximum (IR-07) |
| `syft version` limit | 10 seconds | IR-05 |
| Wait for a killed process tree | at most 5 seconds | U3-NFR-04; normally a few milliseconds |
| Syft error output kept | the last 4 KB | U3-NFR-04 |
| Copy buffer | 80 KiB, pooled | U3-NFR-05 |
| NuGet package caps | 65,534 entries; 1 MB of `.nuspec` | U3-NFR-05 |
| Deletion attempts | 5, 100 to 800 ms apart | IR-13 |
| Live Log replay and subscriber buffer | 200 and 1,000 entries | IR-17 |

An option outside its range stops startup with a message naming it, for example "Airlock:Staging:Root must be a full
path" (E13).
