# U2 Application — NFR Design Patterns

**Stage**: CONSTRUCTION — U2 Application — NFR Design (Standard depth)

| NFR | Pattern | How it is applied |
|---|---|---|
| U2-NFR-01 Dependencies | Abstractions only, guarded by tests | `Airlock.Application.csproj` references `Airlock.Domain` and four packages: `Microsoft.Extensions.Logging.Abstractions`, `Microsoft.Extensions.Options`, `Microsoft.Extensions.DependencyInjection.Abstractions` and `Microsoft.Extensions.Hosting.Abstractions`. Architecture rule 2 checks the referenced assemblies (only `System.*`, `Airlock.Domain` and `Microsoft.Extensions.*`) and that no Application type depends on an `Airlock.Infrastructure`, `Airlock.Web` or `Microsoft.AspNetCore` namespace. Rule 4 checks that no Application type implements a port interface. Rule 6 checks that every class in `Airlock.Application.UseCases` is sealed and that the use cases live there. |
| U2-NFR-02 Concurrency safety | One small lock for the slot; immutable versions everywhere else | `ScanCoordinator` keeps the slot as one immutable state value — idle, reserved (with or without an upload) or running — behind a single `lock`. Each transition is a short critical section that neither awaits nor calls a port; watchers are notified inside it through one-item channels that never block, so every watcher sees the changes in order. Scans are immutable Domain records; the registry holds the latest version of each, and only the scan's pipeline calls `Update` for it. |
| U2-NFR-03 Bounded work | One `Parallel.ForEachAsync`; no retries above the port | Correlation is `Parallel.ForEachAsync` over the merged packages with `MaxDegreeOfParallelism = Correlation.MaxParallelism` (default 4). A package's own lookups run one after another, in candidate order. The correlator calls the catalog once per lookup and treats `CatalogFailed` as final (AR-14); retries, timeouts and the 50-per-30-seconds limiter all sit behind the port in U3. |
| U2-NFR-04 Responsive stopping | One cancellation source per scan, with a recorded cause | Each running scan has a `ScanRun`: a `CancellationTokenSource` linked to the host's stopping token and to a time-limit source created with the `TimeProvider` (`Timeouts.Scan`), plus a stop cause that is set once — the first cause wins: cancelled by request, Emergency Stop, server shutdown or time limit. Every port call receives the run's token, and the token is checked before each Syft run and each lookup. When the pipeline sees cancellation it maps the cause: the time limit fails the scan with `ScanTimedOut` (AR-29); every other cause cancels it with its reason. `CancelScan` sets the cause, cancels, and waits for the run to end with `WaitAsync(Timeouts.CancelGracePeriod, TimeProvider)` (default 5 seconds) before returning the latest version. |
| U2-NFR-05 Outage detection | A per-scan outage breaker | `NvdOutageBreaker` counts failed lookups in a row with `Interlocked`; any answer resets it while it is closed. At `Correlation.OutageThreshold` (default 5) it opens once, logs the outage once and stays open for the rest of the scan. The correlator asks it before every lookup; when it is open, the package is Unverified with "NVD unavailable — not checked after 5 failed lookups in a row". Lookups already in flight are not cancelled. With four lookups in flight the breaker opens after about two rounds of failures, which stays within 5 minutes as long as one lookup — every attempt, backoff and timeout included — ends within 2 minutes (a constraint on U3). |
| U2-NFR-06 Fail-closed guarantees | One exit funnel; results only from complete sets | `ScanPipeline.RunAsync` is one `try`/`catch`/`finally`: cancellation maps to its cause (U2-NFR-04); any other exception fails the scan with `Unexpected` (AR-31) and the full exception goes to the console log only. Correlation results go into an array with one slot per merged package, each written once; the scan finishes only when every slot is filled — otherwise it fails with `Unexpected`. No code path writes a verdict before its lookups have answered, and a final status that cannot be recorded becomes Failed, never a success. A seeded randomized test checks every verdict against an independent copy of the decision tables written in the test project. |
| U2-NFR-07 Bounded memory | A per-subscriber queue that evicts the oldest droppable event | `ScanEventHub` owns the scan's latest version and its subscriptions under one short lock of its own, so a new subscriber's snapshot and the events after it never overlap or leave a gap (refinement 4 of the code generation plan). Each subscription is a small queue of at most 1,000 events: when it is full, the oldest `ScanLogged` or `PackagesCorrelated` event is removed. `ScanSnapshot`, `PhaseChanged` and `ScanFinished` — at most five per scan — are never removed. Publishing appends and signals the reader; it never awaits. `WatchActiveScan` gives each watcher a one-item channel that keeps only the latest state. Uploads pass from the request stream straight to the staging port with a byte budget; the Application never holds a file's content. |
| U2-NFR-08 Time | `TimeProvider` everywhere | `AddAirlockApplication` registers `TimeProvider.System` unless one is already registered. Timestamps come from `GetUtcNow()`; the scan limit is `new CancellationTokenSource(Timeouts.Scan, timeProvider)`; the cancel grace period is `WaitAsync(…, timeProvider)`; durations use `GetTimestamp` and `GetElapsedTime`. The architecture clock rule bans the Domain's five clock reads, `Stopwatch`, timers, `Task.Delay` without a `TimeProvider`, `CancellationTokenSource.CancelAfter` and the `CancellationTokenSource(TimeSpan)` constructors in Application code. |
| U2-NFR-09 Observability and log hygiene | A source-generated catalogue, a scan-id scope and one cleaning helper | `ScanLog` holds one `[LoggerMessage]` method per catalogue line, with stable event ids: 1100s for the scan lifecycle, 1200s for SBOM generation, 1300s for correlation, 1400s for stopping and cleanup. The pipeline runs inside `BeginScope` with a `ScanId` entry, which U3's Live Log provider reads. `ExternalText.Clean(text, 512)` turns CR, LF and tab into spaces, removes other control and bidirectional formatting characters, collapses repeated spaces, trims, and cuts to 512 characters ending with "…"; it is applied to Syft's errors, NVD's errors and user-supplied paths before they are logged or used in a reason. The Application never sees the NVD key — only `IsConfigured` — and refusal messages are fixed texts. |
| U2-NFR-10 Performance | Single-pass merge; copy-on-write subscriber lists | The merge is one pass with a dictionary keyed by `Package` (BR-11 equality) and a set per package for its candidate CPEs. Warnings are built once, at the end. Publishing loops over the current subscriber array. The unit tests assert a generous bound — 10,000 packages with an instant fake catalog in under 10 seconds — and Build and Test measures the 1-second and 10-second targets. |
| U2-NFR-11 Reliable cleanup | Each cleanup step guarded on its own | The pipeline's `finally` runs the AR-32 steps in order, each in its own `try`/`catch` that logs a failure ("⚠️ Cleanup step failed: {step}: {reason}") and carries on; releasing the slot sits in an inner `finally`, so it runs whatever happens before it. `ScanReservation.DisposeAsync` uses the same guarded steps. |
| U2-NFR-12 Portability | Host rules behind one port | Whether a path is absolute, how it normalizes, where its links lead and whether it lies inside a root are all answered by `IHostFileSystem` — including **`IsAbsolute`, added in this stage** — so the Application never applies one operating system's rules itself. The test fake has a Windows mode (drive letters, `\`, case-insensitive) and a Linux mode (`/`, case-sensitive), and the target tests run in both modes on every operating system. |
| U2-NFR-13 Coverage | Fakes that can block and fail | Every port has a fake in `tests/Airlock.Application.Tests/Fakes`. Each fake answers from a table, can hold a call until it is cancelled (to test stopping), can throw on demand (fault injection) and records its calls. Test classes follow the rule-to-test map; coverage comes from `dotnet test --coverage --coverage-output-format cobertura`. |
| U2-NFR-14 Maintainability | Namespaces by responsibility; rule ids in comments | Namespaces as in `logical-components.md`; each rule's code carries a one-line `// AR-nn` comment; public types have one-line XML summaries. |

## Values chosen

| Setting | Default | Allowed | Reason |
|---|---|---|---|
| `Correlation.MaxParallelism` | 4 | 1 to 16 | The keyed NVD rate is 50 requests per 30 seconds, about 1.7 per second. With NVD answering in about a second, two or three lookups in flight keep the limiter busy; four leaves room for slow answers, and more would only wait at the limiter. |
| `Correlation.OutageThreshold` | 5 | 3 to 20 | About two rounds of failures at the default parallelism; few enough to meet U2-NFR-05, enough that one or two unlucky requests never declare an outage. |
| `Timeouts.CancelGracePeriod` | 5 seconds | 0 to 10 seconds | U2-NFR-04 |
| `Timeouts.Scan` | 60 minutes | 1 minute to 24 hours | FR-15 |
| `Timeouts.SyftRun` | 15 minutes | 1 minute up to `Timeouts.Scan` | FR-05 |
| `Limits.MaxArtifactsPerScan` | 25 | 1 to 1,000 | FR-02 |
| `Limits.MaxBytesPerScan` | 2 GiB | at least 1 MiB | FR-02; U4 sets the server's request-body limit to match |
| `Retention.Duration` | 24 hours | 1 minute to 30 days | FR-19 |
| `Retention.MaxScans` | 20 | 1 to 1,000 | FR-19 |
| `AllowedScanRoots` | empty | each an absolute path | A root that does not exist at startup is logged as a warning, not an error, because a volume may be mounted later |
| Events kept per subscriber | 1,000 | fixed | U2-NFR-07 |

An option outside its range stops startup with a message naming it, for example "Airlock:Correlation:MaxParallelism
must be between 1 and 16" (E13).
