# U2 Application — NFR Requirements

**Stage**: CONSTRUCTION — U2 Application — NFR Requirements (Standard depth)

Only what is specific to `Airlock.Application`; system-wide NFRs stay in `inception/requirements/requirements.md`, and
U1's apply to the Domain types the Application uses. Values marked "NFR Design" are chosen in the next stage within
the bounds given here.

| ID | Quality | Requirement | Check | Trace |
|---|---|---|---|---|
| U2-NFR-01 | Dependencies | `Airlock.Application` references `Airlock.Domain` and only the Microsoft.Extensions abstraction packages — never Infrastructure, Web or `Microsoft.AspNetCore.*`. Port interfaces live in the Application and are implemented only in Infrastructure; use cases are sealed classes in `Airlock.Application.UseCases`. | Architecture rules 2, 4 and 6, each with a positive control | NFR-02; N7 |
| U2-NFR-02 | Concurrency safety | The active slot admits exactly one holder however many reservations race for it. A scan has one writer; readers receive immutable versions. No lock is held across an `await` or while a port is called. | Stress test: 100 concurrent reservations, exactly one succeeds and 99 are refused `ScanInProgress`, repeated 50 times; Emergency Stop racing the end of a scan yields exactly one final status | FR-04; AR-02, AR-21; defect 15 |
| U2-NFR-03 | Bounded work | At most `Correlation.MaxParallelism` packages are correlated at once (NFR Design, between 1 and 16). Every NVD request goes through the catalog port, whose shared limiter (U3) keeps the rate at 50 requests per 30 seconds. The Application never retries a lookup itself: retries belong to the catalog, and its `CatalogFailed` is final. | A fake catalog records the peak number of lookups in flight and the number of calls per package | NFR-04, NFR-05; AR-14, AR-17 |
| U2-NFR-04 | Responsive stopping | After cancel, Emergency Stop, the time limit or shutdown, no new Syft run or lookup starts. When the ports honour cancellation, the final status is recorded within 2 seconds. `CancelScan` waits at most `Timeouts.CancelGracePeriod` (NFR Design, at most 10 seconds). | Tests with fakes that block until cancelled; the 60-minute limit on a fake clock | FR-15, FR-16; AR-27 to AR-30; defect 3 |
| U2-NFR-05 | Outage detection | After `Correlation.OutageThreshold` failed lookups in a row (NFR Design, between 3 and 20), no further lookup starts. With U3's retry policy, an unreachable NVD ends a scan within 5 minutes of its first failed lookup. | Unit test: zero lookups after the threshold, whatever the parallelism; the 5-minute bound is measured in Build and Test against a stub NVD | Q-U2-2; AR-18; ADR-0002 |
| U2-NFR-06 | Fail-closed guarantees | No path produces a clean package without the lookups the decision tables require having answered. Every exception, cancellation and timeout ends a scan Failed or Cancelled with no partial result. Every finished scan has total = clean + vulnerable + unverified, and no package is lost or counted twice between merge and finish. | Seeded randomized tests over fake catalogs: every verdict matches the decision tables and the totals add up; fault injection at every port call never yields Completed or Incomplete | ADR-0002; NFR-03; AR-09, AR-14 to AR-16, AR-20, AR-31 |
| U2-NFR-07 | Bounded memory | Each subscriber's buffer is bounded (size in NFR Design) and the pipeline never waits for a subscriber. Retention keeps at most `Retention.MaxScans` finished scans. Uploads stream to disk through the staging port and are never held whole in memory. | A subscriber that never reads neither slows nor blocks a scan and loses only log and progress events | NFR-05; AR-23, AR-33 |
| U2-NFR-08 | Time | All time comes from an injected `TimeProvider`: scan timestamps, the 60-minute limit, grace periods and retention. No direct clock reads, and no delays or timers outside the `TimeProvider`. | Architecture test: no clock reads in `Airlock.Application`, as for the Domain; tests advance a fake clock by 60 minutes and 24 hours without waiting | NFR-09; AR-29, AR-33 |
| U2-NFR-09 | Observability and log hygiene | Every pipeline log entry is written in a logging scope that carries the scan id. Messages are the log catalogue's, as source-generated logging methods with stable event ids. External text is cleaned (AR-25) before it is logged. No log line or refusal contains the NVD key, environment values or a stack trace. | Tests on a fake logger assert the catalogue's messages, levels and scope; a Syft error output with ANSI escapes, CR and LF comes out as one clean line | NFR-03, NFR-07; FR-18; AR-24, AR-25 |
| U2-NFR-10 | Performance | The Application adds little to NVD's time. With a fake catalog that answers at once, a 281-package scan (S0 S10) completes in under 1 second and a 10,000-package scan in under 10 seconds. Publishing an event costs time in proportion to the number of subscribers and never blocks the writer. | Measured in Build and Test (performance instructions), with a generous bound asserted in the unit tests | NFR-05 |
| U2-NFR-11 | Reliable cleanup | Cleanup (AR-32) runs on every exit path, and each step runs even when an earlier one throws. A staging area that cannot be deleted is logged and the slot is still released, so the slot can never stay held after a scan ends. | Fault injection: staging disposal, a registry update or an event publish throws, and the slot is still released | NFR-04; FR-03, FR-04; AR-32 |
| U2-NFR-12 | Portability | The path rules (AR-05, AR-07) behave the same on Windows and Linux, using the host's own case rules through `IHostFileSystem`. No Application code depends on the directory separator or the operating system. | Target-validation tests run against a fake host file system in Windows and Linux modes, on every operating system | NFR-06 |
| U2-NFR-13 | Testability and coverage | Every rule AR-01 to AR-35 has tests (the rule-to-test map). Every port has an in-memory fake. Coverage of `Airlock.Application` is at least 90 % of lines and 85 % of branches. | Coverage report from `dotnet test`; enforced in CI from U6 | NFR-09 |
| U2-NFR-14 | Maintainability | Names follow GLOSSARY.md; each rule's implementation carries a one-line comment naming its AR id; use cases are plain classes; warnings are errors. | Build | NFR-08; N7 |
