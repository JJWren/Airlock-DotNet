# U4 Web API — NFR Requirements

**Stage**: CONSTRUCTION — U4 Web API — NFR Requirements (Standard depth)

Only what is specific to the host and the `/api/v2` surface; system-wide NFRs stay in
`inception/requirements/requirements.md`, and the constraints U2 and U3 hand to U4 are requirements here. Values marked
"NFR Design" are chosen in the next stage within the bounds given. The UI's own qualities (U5) are not covered.

| ID | Quality | Requirement | Check | Trace |
|---|---|---|---|---|
| U4-NFR-01 | Architecture | `Airlock.Web` references `Airlock.Infrastructure`, `Airlock.Application`, `Airlock.Domain` and its Web packages. The API's types call Application use cases only; `AirlockHost`, the composition root that `Program` calls, is the only Web code that names Infrastructure types. | Architecture rule 5 for the API, with a positive control | NFR-02; WR-23 |
| U4-NFR-02 | Streaming uploads | A submission is read part by part with a multipart reader, and each artifact goes on as a stream: nothing calls `ReadFormAsync`, binds an `IFormFile` or turns on request buffering, so ASP.NET Core never holds an artifact in memory or spools it to a file of its own, up to `Limits.MaxBytesPerScan` (2 GiB) and its framing. | A generated 256 MiB upload through the test server is staged with under 32 MB allocated (in a collection that runs alone); in Build and Test, a 1 GiB upload through Kestrel grows the working set by under 100 MB | NFR-05; WR-07, WR-08; U3-NFR-05 |
| U4-NFR-03 | Request limits | `POST /api/v2/scans` raises its own body limit to `Limits.MaxBytesPerScan` plus at most 1 MiB for the multipart framing (the allowance is set in NFR Design), and every other request keeps a 1 MiB limit, so the `too-large` refusal answers first and the server's limit is only a backstop (WR-08). The reader bounds each part's headers in count and length. The limits follow the configured `Limits.MaxBytesPerScan`; there is no second setting. | On a real Kestrel (`UseKestrel`) with a lowered limit: an upload just under it passes; one over it gets 413 `too-large` as a ProblemDetails; an oversized body sent to another endpoint is cut off | FR-02; N3; WR-08; U2's constraint on U4 |
| U4-NFR-04 | Stalled clients | An upload that delivers no bytes for 60 seconds is ended as if its client had disconnected: the reservation is disposed, the slot freed and the staging area deleted, so a half-open connection cannot hold the single active slot. A client that disconnects mid-upload frees the slot at once. Kestrel's own protections — minimum data rates, the request-header timeout — keep their defaults. | On a fake clock, a body that stops for 60 seconds frees the slot and leaves the staging root empty; a disconnect frees the slot at once | FR-04; WR-07; services.md (cancellation) |
| U4-NFR-05 | Event streams | Every event is written and flushed as it happens, never buffered or compressed. A stream silent for 15 seconds receives a `: keep-alive` comment line, which clients ignore, so proxies keep it open while Syft works and a vanished client is noticed at the next write. A client that closes its connection ends its subscription within a second. Stopping the server ends every open stream within a second — a scan's stream with its `finished` event, once the scan is cancelled (U2 AR-30) — so shutdown never waits for clients. | An event arrives without waiting for the next one; the comment after 15 seconds of fake time; the scan's subscriber count drops after a disconnect; stopping the host ends a Live Log stream | FR-17, FR-18; WR-12, WR-13, WR-18 |
| U4-NFR-06 | Security | API answers carry `X-Content-Type-Options: nosniff`, because their JSON is written unescaped (WR-02), and no `Server` header; no CORS headers are ever sent (WR-19 relies on it); nothing is compressed. No answer carries exception details in any environment, Development included: the API's own error handling runs before the developer exception page. Cross-site `POST` requests and unknown host names are refused (WR-19, WR-20). The NVD key appears in no answer and no log line (U3-NFR-07). Airlock serves plain HTTP, as the original did; TLS is a reverse proxy's job, which the README explains (U6), and `localhost` counts as a secure context for the UI's clipboard. | The headers on every endpoint; a 500 in Development without details; a full scan through the API, logged at Debug, with the key in no answer and no line | NFR-03; WR-05, WR-19, WR-20; ADR-0007 |
| U4-NFR-07 | Offline docs | The OpenAPI 3.1 document is served at `/openapi/v2.json`, and `/docs` makes no request to any other host: Scalar's assets come from Airlock, and its default fonts, its AI agent and its request proxy are off, so the docs work on a network without internet access and send nothing about the API anywhere. | The `/docs` page and every asset it loads reference no other host; the document parses as OpenAPI 3.1 and lists every endpoint (WR-22) | FR-20; WR-22; NFR-03 |
| U4-NFR-08 | Performance | Refusals made before the body is read (403, 409, 415, 503) answer within 100 ms once Syft's status is cached; `GET /api/v2/scans/{id}` of a 500-finding scan within 250 ms; health within 50 ms from the cached status; an event reaches its client within 100 ms of being published. The scan runs off the request, so the API adds nothing to a scan's duration. | Generous bounds asserted in the tests; measured in Build and Test (performance instructions) | NFR-05; WR-06, WR-10, WR-17 |
| U4-NFR-09 | Reliability | A misbehaving client — a malformed body, a disconnect mid-upload, a stalled upload, a slow or vanished stream reader — never leaks the active slot, a staging folder or a subscription, and never affects another client or the running scan. A second Airlock started on a staging root that a running one holds stops at startup with a message naming the root (U3: one Airlock per staging root). | After each such test: the slot free, the staging root empty, the scan's subscriber count back to zero; a second host on the same root fails to start, naming it | FR-03, FR-04; WR-07; U3's constraint on U4 |
| U4-NFR-10 | Startup | The host starts with its defaults alone and never waits for Syft or NVD; options are validated at startup and an invalid one stops it with a message naming the option; a missing NVD key or Syft starts Airlock DEGRADED; the original variable names are honoured; `AllowedHosts` defaults to `localhost`, `127.0.0.1` and `[::1]`. | `HostCompositionTests` | E13; WR-20, WR-23; U3-NFR-11 |
| U4-NFR-11 | Observability | The Web logs in `Airlock.Web.*` categories, which reach the Live Log: each refusal it makes itself — cross-site, unsupported media type, invalid request — at Warning, with any text from the client cleaned (U2 AR-25); each unexpected exception at Error, its details on the console only. ASP.NET Core's own request logging stays at Warning by default, so the console shows Airlock's activity, and `LOG_LEVEL` still sets the console's level. | Tests on a fake logger: the lines, their levels, cleaned client text, no exception details in the Live Log | NFR-07; WR-05; U3 IR-15 |
| U4-NFR-12 | Portability | The API behaves the same on Windows and Linux; its tests run on both in CI (U6). | CI | NFR-06 |
| U4-NFR-13 | Testability | No API test needs the network, Syft or NVD: `WebApplicationFactory` hosts the real Application and Infrastructure with fakes for the SBOM generator and the vulnerability catalog, staging under a temporary root of each test's own, and a fake clock where Airlock's own timing matters. Tests that need Kestrel's own limits or host handling run on a real Kestrel through `UseKestrel`. | The suite passes with the network off and no Syft installed | NFR-09 |
| U4-NFR-14 | Coverage | Every rule WR-01 to WR-23 has its check in the rule-to-test map. Coverage of `Airlock.Web` at the end of U4 is at least 90 % of lines and 85 % of branches, as for the Application. | Coverage report from `dotnet test`; enforced in CI from U6 | NFR-09 |
| U4-NFR-15 | Maintainability | Endpoint handlers stay thin: they read the request, call one use case and map its outcome. DTO mapping lives in `ScanDtoMapper`, problems in `ApiProblems`, multipart reading in `MultipartScanReader`, event writing in one stream writer. Each rule's code names its WR id in a one-line comment; names follow GLOSSARY.md; warnings are errors. | Build | NFR-08 |
