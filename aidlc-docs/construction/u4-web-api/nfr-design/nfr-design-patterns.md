# U4 Web API — NFR Design Patterns

**Stage**: CONSTRUCTION — U4 Web API — NFR Design (Standard depth)

| NFR | Pattern | How it is applied |
|---|---|---|
| U4-NFR-01 Architecture | Namespaces, guarded by rule 5 | `Airlock.Web.csproj` uses the Web SDK and references the three Airlock projects, `Microsoft.AspNetCore.OpenApi` and `Scalar.AspNetCore`. The API lives under `Airlock.Web.Api.*` (`logical-components.md`), and rule 5 checks that no Web type but the composition root, `AirlockHost`, depends on an `Airlock.Infrastructure` type; its positive control is `AirlockHost`, which does. Every Web type is internal; the only public one is the `Program` class .NET 10 generates for tests. |
| U4-NFR-02 Streaming uploads | A forward-only reader over the raw body | `MultipartScanReader` checks the boundary (`MediaTypeHeaderValue`, at most 70 characters, RFC 2046), then walks the sections with `MultipartReader` over `Request.Body`, which is never buffered. A `targetPath` section is decoded as strict UTF-8 through a 16 KiB cap; an `artifacts` section's body goes as a stream straight to `ScanReservation.AddArtifactAsync`, which copies it to disk through U3's pooled 80 KiB buffer. Nothing touches `Request.Form`, `IFormFile` or `EnableBuffering`, so ASP.NET Core neither buffers nor spools. The check sends a generated 256 MiB artifact through `MultipartFormDataContent` over a source stream that allocates nothing, and measures `GC.GetTotalAllocatedBytes(true)` around the request, in a test collection that runs alone. |
| U4-NFR-03 Request limits | A small server-wide limit, raised by the one endpoint that needs more | Kestrel's `Limits.MaxRequestBodySize` is 1 MiB. The submission sets `IHttpMaxRequestBodySizeFeature.MaxRequestBodySize` to `Limits.MaxBytesPerScan` plus 1 MiB after the reservation succeeds and before it reads anything, so a request refused earlier (403, 409, 415, 503) keeps the small limit and Kestrel drops its unread body quickly. The `too-large` refusal stops the reading at `Limits.MaxBytesPerScan`; if Kestrel's raised limit is reached first, the `BadHttpRequestException` it throws mid-read becomes the same `too-large` problem. `MultipartReader` keeps its defaults of at most 16 headers and 16 KiB of headers per part. |
| U4-NFR-04 Stalled clients | An idle timer around the body | The reader wraps `Request.Body` in `IdleTimeoutStream`: each read that returns data restarts a 60-second `ITimer` from the `TimeProvider`, and when the timer fires it cancels the read in progress. The endpoint treats that like `RequestAborted`: the reservation is disposed (slot, staging area), "upload stalled" is logged, and the connection is aborted with `HttpContext.Abort()`, since nobody is listening for an answer. `RequestAborted` itself ends the reading at once when the client disconnects. Kestrel's minimum data rates and header timeout keep their defaults. |
| U4-NFR-05 Event streams | One writer for both streams | `EventStreamResult`, an `IResult`, sets `Content-Type: text/event-stream`, `Cache-Control: no-store` and `X-Accel-Buffering: no` (so an nginx proxy passes events on at once), disables response buffering (`IHttpResponseBodyFeature.DisableBuffering`), and enumerates the use case's `IAsyncEnumerable`. Each item becomes an `event:` line and one `data:` line of compact JSON, then a flush. While it waits for the next item it races a 15-second delay on the `TimeProvider` against the pending move-next; when the delay wins it writes `: keep-alive` and flushes, keeping the same pending move-next. Its token links `RequestAborted` with a cancellation that fires 1 second after `ApplicationStopping`: a closed connection ends the subscription at once, and shutdown ends every stream within a second. A scan's stream normally ends before that, with `finished`, because the Application cancels running scans as the host stops (U2 AR-30). No response compression is registered. |
| U4-NFR-06 Security | Headers set once for `/api`; errors handled before the developer page | Kestrel's `AddServerHeader` is false. For requests under `/api`, a small middleware adds `X-Content-Type-Options: nosniff` and `Cache-Control: no-store` through `Response.OnStarting`. No CORS services, no CORS middleware and no response compression are registered. `UseExceptionHandler` and `UseStatusCodePages` run in a branch for `/api` (`UseWhen`), so API errors become problems in every environment — the developer exception page that `WebApplication` adds in Development never sees them — while the UI keeps its own error handling (U5). The cross-site check (WR-19) is an endpoint filter on the three `POST` endpoints; host filtering is ASP.NET Core's `HostFilteringMiddleware`, which `WebApplication` runs first, configured by `AllowedHosts`. Kestrel listens on HTTP only; no HTTPS redirection or HSTS is added. |
| U4-NFR-07 Offline docs | Scalar configured to stay at home | `MapScalarApiReference("/docs", …)` with `DefaultFonts = false` (otherwise Scalar's fonts come from its CDN), `Telemetry = false` (on by default, it reports whether a request was sent through Scalar's client) and `DisableAgent()` (Scalar's AI chat, which works on localhost without a key). `ProxyUrl` stays null — no proxy, the default — and the bundled assets stay the default (`BundleUrl` unset). The document comes from `MapOpenApi()` at `/openapi/v2.json`, Scalar's default `OpenApiRoutePattern`. The test reads `/docs` and checks that its HTML and the configuration it embeds name no other host and carry the three settings; Build and Test opens `/docs` in a browser and confirms from the network log that no request leaves the machine. |
| U4-NFR-08 Performance | Nothing on the request path but the use case | The submission reserves before reading and answers as soon as the scan starts; reads take the registry's immutable versions without locking (U2 AR-21); JSON is written from a source-generated context; events are written as they arrive. The unit tests assert bounds ten times the targets; Build and Test measures the targets themselves. |
| U4-NFR-09 Reliability | Every exit disposes; a lock per staging root | The submission holds its reservation in `await using`, so a refusal, an exception, an abort or a stalled upload all dispose it (U2 AR-03). A stream unsubscribes when its token ends, through `await foreach`'s disposal of the use case's enumerator. U3's `StagingSweepService` first takes an exclusive lock on `<Staging:Root>/.airlock-lock` — a `FileStream` opened with `FileShare.None` and kept open until the host stops, which .NET turns into an advisory `flock` on Linux — and only then sweeps. When another Airlock holds the lock, startup stops with "Another Airlock is using the staging root <root>". The operating system releases the lock if Airlock crashes. This is a small amendment to U3's code, made in U4 Code Generation. |
| U4-NFR-10 Startup | Defaults that work | `appsettings.json` carries the defaults: `AllowedHosts` set to `localhost;127.0.0.1;[::1]`, and console logging at Information with `Microsoft.AspNetCore` at Warning. Options are validated on start (U2, U3), and Syft is probed on first use, not at startup (U3). The composition test starts the real host with these defaults. |
| U4-NFR-11 Observability | A catalogue in `Airlock.Web` | `WebLog`, with `[LoggerMessage]` methods and stable event ids: 3100s for submissions (3101 cross-site request refused, 3102 unsupported media type, 3103 invalid request, 3104 upload stalled, 3105 upload ended by the client), 3201 for an unexpected error (Error, with the exception, which the Live Log provider drops — U3 IR-15), and 3301 for a stream ended by shutdown (Debug). Client text — a field name, an `Origin` — goes through U2's `ExternalText.Clean` before it is logged. |
| U4-NFR-12 Portability | No operating-system code in the Web | The Web has no operating-system branches; CI runs the API tests on Windows and Linux (U6). |
| U4-NFR-13 Testability | One factory, two servers | `AirlockWebFactory`, a `WebApplicationFactory<Program>`, replaces `ISbomGenerator` and `IVulnerabilityCatalog` with hand-written fakes, `TimeProvider` with a `FakeTimeProvider` where a test needs one, and sets `Airlock:Staging:Root` to a temporary folder of its own. The body-limit tests call `UseKestrel()`; everything else uses the test server. Tests send `Sec-Fetch-Site`, `Origin` and `Host` explicitly where a rule depends on them. |
| U4-NFR-14 Coverage | The rule-to-test map, plus this stage's checks | Test classes follow the map in `business-logic-model.md` and the checks in `logical-components.md`; coverage comes from `dotnet test --coverage --coverage-output-format cobertura`. |
| U4-NFR-15 Maintainability | Namespaces by concern; rule ids in comments | Namespaces as in `logical-components.md`. Each rule's code carries a one-line `// WR-nn` comment, and handlers stay thin: read, call one use case, map the outcome. |

## Values chosen

| Setting | Default | Allowed | Reason |
|---|---|---|---|
| `AllowedHosts` | `localhost;127.0.0.1;[::1]` | host names separated by `;`, or `*` for any | WR-20; ADR-0007 |

| Fixed value | Size | Reason |
|---|---|---|
| Server-wide request-body limit | 1 MiB | U4-NFR-03: only the submission reads a body |
| Submission's body limit | `Limits.MaxBytesPerScan` + 1 MiB | U4-NFR-03: 25 parts' headers and boundaries take a few KiB |
| `targetPath` value read | at most 16 KiB of UTF-8 | WR-07: 4,096 characters at up to 4 bytes each |
| Multipart boundary | at most 70 characters | RFC 2046 |
| Part headers | at most 16, and 16 KiB in total, per part | `MultipartReader`'s defaults |
| Unknown field name shown | at most 64 characters | WR-07 |
| Upload idle timeout | 60 seconds | U4-NFR-04: long enough for any working client, short enough to free the slot |
| Keep-alive comment | after 15 seconds of silence | U4-NFR-05: under common proxy idle timeouts, such as nginx's 60 seconds |
| Streams after shutdown begins | end within 1 second | U4-NFR-05 |
| Kestrel minimum data rates and header timeout | ASP.NET Core's defaults | U4-NFR-04 |
| Web log event ids | 3100 to 3399 | After U2's 1100s and U3's 2100s to 2500s |
