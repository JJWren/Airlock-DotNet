# U6 Delivery — NFR Requirements

**Stage**: CONSTRUCTION — U6 Delivery — NFR Requirements (Standard depth)

Only what is specific to building, checking, publishing and running Airlock. System-wide NFRs stay in
`inception/requirements/requirements.md`, and U1 to U5's still hold for the code the image carries. The answers were
Q-U6-N1 to Q-U6-N4 = A (`../../plans/u6-delivery-nfr-requirements-plan.md`). Where a target amends a functional design
rule, `../functional-design/business-rules.md` says so (DR-27 to DR-31 were added for these answers). Values marked
"Infrastructure Design" are chosen there, within the bounds given. U6's NFR Design amended U6-NFR-01, U6-NFR-02,
U6-NFR-07 and U6-NFR-09 (`../nfr-design/nfr-design-patterns.md`).

| ID | Quality | Requirement | Check | Trace |
|---|---|---|---|---|
| U6-NFR-01 | Supply chain: pinning | Every action in the workflows is named by its full 40-character commit SHA, with the version it stands for as a comment. Every `FROM` in the `Dockerfile` names its image by tag and digest (`@sha256:`). Every tool CI fetches — Syft, Grype, actionlint, zizmor — is pinned to a version and, before it runs, checked against a checksum or digest committed in this repository, not only against a checksums file fetched beside it (NFR Design). The one exception is Airlock's own image in the compose file, which `docker compose up` takes by the tag in `AIRLOCK_IMAGE_TAG` (Q-U6-2). | zizmor in CI's lint job, set to require a SHA for every action, GitHub's own included; a repository test that every `FROM` carries a digest and every tool a checksum or digest | NFR-11; Q-U6-N4; DR-27 |
| U6-NFR-02 | Supply chain: updates | Dependabot proposes updates weekly for NuGet, the Docker images, GitHub Actions and the .NET SDK in `global.json`, keeping the pins and their version comments. Minor and patch updates are grouped per ecosystem; a major update comes on its own. Major updates of the .NET SDK, Microsoft's .NET images and the `Microsoft.Extensions.*` and `Microsoft.AspNetCore.*` packages are not proposed, so Airlock stays on .NET 10 LTS (NFR Design). A version update waits 7 days after its release (`cooldown`). Security updates, Microsoft's .NET images and the .NET SDK do not wait: their updates carry security fixes, and Dependabot raises no alert for images or the SDK. Syft still changes by hand, in all its places at once (DR-04, DR-16). | A repository test reads `dependabot.yml`: the four ecosystems, the schedule, the groups, the cooldown and its exceptions, and the LTS rule; Dependabot's first runs after the push | NFR-11; Q-U6-N4; DR-16, DR-27 |
| U6-NFR-03 | Supply chain: what CI runs | The workflows use GitHub's own actions only (`actions/*`, `github/*`). Docker, Syft, Grype, actionlint and zizmor run as command-line tools (U6-NFR-01). Jobs run on GitHub-hosted runners named by image — `ubuntu-24.04` and `windows-2025` — rather than `-latest`, so a change of runner arrives as a reviewed edit. | A repository test lists the owner of every `uses:` and every `runs-on` | NFR-11; DR-12, DR-28 |
| U6-NFR-04 | Workflow security | Workflows grant `contents: read`. A job asks for more only where it needs it: CodeQL's `security-events: write`, and the publishing job's `packages: write`, `id-token: write` and `attestations: write`. Checkout keeps no credentials. No workflow runs on `pull_request_target` or `workflow_run`. Values from outside — branch, tag and pull-request names — reach scripts through environment variables, never through `${{ }}` inside a script. The release runs only in `JJWren/Airlock-DotNet` and only on a version tag. It restores no cache, so nothing an earlier run left can reach the published image. Every job has a time limit. A newer push cancels an older CI run of the same branch, but never a release. | actionlint and zizmor in CI's lint job fail the run on any finding that `.github/zizmor.yml` does not accept with a reason; a repository test for the permissions and the release's guards | NFR-03, NFR-11; DR-11, DR-19, DR-23, DR-28 |
| U6-NFR-05 | Secrets | The NVD key is never in the image, the build context (DR-06), a build argument, a label, a log or CI. CI holds no secret besides each run's own `GITHUB_TOKEN`. The smoke test's stand-in key is a fixed value written in the workflow, one NVD would refuse, and it is used only against an NVD that cannot be reached. It must not appear in the container's log, as U3 requires of a real key. Compose takes `NVD_API_KEY` from `.env` only. | A repository test: no `ARG` or `ENV` in the `Dockerfile` names a key, and `.env*` is in `.dockerignore`; the smoke test searches the container's log and the image's configuration for the stand-in key | NFR-03; E13; Q-U6-1; DR-06 |
| U6-NFR-06 | Vulnerability management | Three layers. NuGet's audit fails the restore when a package Airlock uses has a published advisory, since warnings are errors. Dependabot proposes updates (U6-NFR-02). Grype scans the image CI builds, through the SBOM Syft makes of it, in CI and again in the release before anything is pushed. A High or Critical vulnerability with a fixed version fails the run (Q-U6-N2). The report, every severity included, is kept with the run. A finding is accepted only in `.grype.yaml`, which names the vulnerability and the package and gives a reason and a date to review it by. When the fix waits on someone else's release — Microsoft's image, Syft, or Go itself — the acceptance lasts until that release. | The image job, in CI and in the release; a repository test that every `.grype.yaml` entry names its package and has a reason and a review date still to come, so a passed date fails CI until someone reviews the finding | NFR-11; Q-U6-N2; ADR-0002; DR-30 |
| U6-NFR-07 | Release integrity | A release builds the image once from the tagged commit, smoke-tests it (U6-NFR-12) and scans it (U6-NFR-06). It then pushes that same image: the pushed image's ID (its configuration digest) equals the tested one's. For each published version, GitHub stores signed build provenance and a signed SBOM made by Syft as artifact attestations, bound to the image's digest and pushed to GHCR beside the image (Q-U6-N3). The tags `X.Y.Z` and `latest` (only for a version with no pre-release suffix) are set only after both attestations are stored and verify with `gh attestation verify` (NFR Design). No tag ever names an image without them, and a failed step leaves the version untagged. Attestations need a public repository; a private one would need GitHub Enterprise Cloud. | A repository test for the release's step order and permissions; every release compares the pushed image's ID with the tested one's and verifies the attestations before tagging; at the first release, after the owner pushes, `gh attestation verify` succeeding for the provenance and the SBOM of `ghcr.io/jjwren/airlock-dotnet:2.0.0`, as the README shows it | NFR-11; E15; Q-U6-2, Q-U6-N3; DR-21, DR-22, DR-31 |
| U6-NFR-08 | Runtime image | The runtime stage is `mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled-extra` (Q-U6-N1): Ubuntu 24.04's libraries for .NET, with ICU and time-zone data (U5-NFR-09), no shell and no package manager. Its default user is the non-root `app` (UID 1654). Airlock's files and Syft belong to root, and `app` cannot change them (DR-03). Nothing depends on a shell: the entry point, Syft's runs and the health check are executables with arguments. | A repository test reads the runtime `FROM`; the smoke test sees the process run as UID 1654 and the scan and its PDF work (U6-NFR-12); Build and Test sees Reports convert times to the browser's time zone with Airlock in the container | U5-NFR-09; Q-U6-N1; DR-02, DR-03 |
| U6-NFR-09 | Runtime hardening | Compose runs the container with a read-only root filesystem. Only three places are writable: the staging root, which holds uploads and Syft's temporary files; beside it on the same volume, the folder where ASP.NET Core keeps its data-protection keys, so that they survive a restart (NFR Design); and a small `/tmp` in memory. Every Linux capability is dropped and `no-new-privileges` is set. An init process forwards signals and reaps child processes. The compose file mounts no Docker socket, asks for no privileged mode or host network, and publishes the port on 127.0.0.1 only (DR-07). | A repository test reads these settings from `docker-compose.yml`; the smoke test's scan runs under them (U6-NFR-12) | NFR-03; DR-03, DR-07, DR-29 |
| U6-NFR-10 | Disk | Uploads, Syft's unpacked copies and its temporary files land on the staging volume — never in memory or in the container's own layer. Syft's temporary files already follow the staging folder (U3 IR-01). The image sets the staging root on the volume, so it never falls back to the system's temporary folder, which is `/tmp` and in memory (U6-NFR-09). The README asks for about three times the largest upload in free space for the volume (U4). A scan's folder is deleted when the scan ends, and the next start sweeps any that a crash left (U3). | A repository test: the staging root the image sets lies under the volume's mount; the smoke test's scan writes there under a read-only root | NFR-04, NFR-05; FR-03; U4-NFR-09 |
| U6-NFR-11 | Health and restarts | The image's health check runs a small probe that ships with Airlock (Q-U6-N1). It asks `GET /api/v2/system/health` on `localhost:8080` and reports healthy on a 200, DEGRADED included (DR-10), giving up after a few seconds. It starts no Syft process, since Syft's status is cached (U3 IR-05). It adds no line to the console at Information and none to the Live Log. The container reports healthy within 30 seconds of starting on a GitHub-hosted runner, and restarts `unless-stopped` (DR-07). Stopping the container during a scan cancels the scan within the 10-second grace period: Syft's process tree is killed and the scan's folder deleted (U3-NFR-04). The next start sweeps anything left. | The smoke test: healthy within 30 seconds, and no health line in the log over a minute at `Information`; Code Generation checks that the health path writes nothing to Airlock's log categories; Build and Test stops the container during a scan and finds no staging folder after the next start | NFR-04, NFR-07; DR-10 |
| U6-NFR-12 | Testability: the image | CI's image job tests the image it built under the compose file's settings, in two phases. **Without a key**: health answers 200 with DEGRADED, the Syft check passing with `1.55.0` and the NVD key check failing; Control Center's page and the stylesheets it names answer 200; a scan is refused with 503 and the missing-key problem; the process runs as UID 1654. **With the stand-in key and `Nvd:BaseUrl` at a closed port on 127.0.0.1**: a scan of a small `requirements.txt` in `/uploads` ends Incomplete, with every package Syft found in it Unverified — ADR-0002's fail-closed path, in the shipped image — and its PDF downloads; the log holds no stand-in key. On a failure the job prints the container's log; at the end it removes the container and its volume. The release runs the same tests on the image it is about to push. | The image job on every pull request, push to `main` and release | NFR-09; E14; Q-U6-1; ADR-0002; DR-13 (amended) |
| U6-NFR-13 | Performance budgets | The image downloads in at most 150 MiB for linux/amd64, measured at Code Generation and reported by every CI run. About 110 MiB is expected: the base is 69.2 MiB, and Syft and Airlock add the rest. A pull request's checks finish within 20 minutes, and a release within 30. Each job's time limit sits a little above its usual length, so a hung job fails instead of running for GitHub's six hours. | CI's run summary (the image's size, the jobs' durations) | NFR-05 |
| U6-NFR-14 | Portability | The image is linux/amd64 only (DR-22). It runs on Docker Engine or Docker Desktop with Compose v2 (`docker compose`); other engines are untested. Running from source works on Windows, Linux and macOS: CI covers Windows and Linux, and macOS relies on .NET's and Syft's own support. | CI on `ubuntu-24.04` and `windows-2025`; the README | NFR-01, NFR-06; E14 |
| U6-NFR-15 | Maintainability | Each tool's version lives in one place, or a repository test checks that its places agree: Syft's four (DR-04), and those of Grype, actionlint and zizmor, each with its checksum or digest. Dependabot keeps current what it can see (U6-NFR-02); Infrastructure Design says how the CI tools' versions stay current. `release.yml` runs `ci.yml` through `workflow_call` instead of repeating its jobs. Each workflow, job and script names the DR and U6-NFR rules it serves in a one-line comment, as Airlock's code names its rules. | Repository tests; review at Code Generation | NFR-08; DR-04 |
| U6-NFR-16 | Observability | The container logs to standard output in Airlock's single-line UTC format at `LOG_LEVEL` (NFR-07), read with `docker compose logs`. A clean start under the default compose file logs no warning that the README does not explain. Each CI run writes a summary: the tests per project, each project's coverage against its target, the image's download size, Grype's counts by severity and fix state, and the accepted findings. The coverage reports, Grype's report and the SBOM are kept as the run's artifacts for 14 days. | The smoke test lists the start's warnings against the README's list; the summary of the first CI run | NFR-07; DR-12, DR-14 |
| U6-NFR-17 | Licensing | As DR-05 and DR-18. The base image's own licence and copyright files stay in the image, and `THIRD-PARTY-NOTICES.md` says where they are. The published SBOM (U6-NFR-07) lists every component Syft finds in the image, with the licences it reports. | Repository tests (DR-05, DR-18); Infrastructure Design lists the base image's licence files | NFR-10; DR-05, DR-18 |

## Taken by default (object at the gate if any is wrong)

- **The .NET SDK skips the cooldown**, as Microsoft's images do. Q-U6-N4 named only the images, but the reason is the
  same: SDK updates carry security fixes, and Dependabot raises no alert for them.
- **A passed review date fails CI.** An accepted Grype finding past its review date stops every run until someone
  renews it with a reason or removes it, so an acceptance cannot outlive its review unnoticed.
- **Tags come last.** The release pushes the image before tagging it, and sets `X.Y.Z` and `latest` only after the
  attestations are stored; the image pushed must have the tested image's ID. How the image is pushed without a tag is
  Infrastructure Design's.
- **Only the permissions Q-U6-N3 named.** `actions/attest` can also record where an artifact is stored, which needs
  `artifact-metadata: write`. Airlock switches that record off, so the publishing job needs `id-token: write` and
  `attestations: write` beside `packages: write`, and nothing more.
- **The smoke test runs a real scan**, with the stand-in key and NVD unreachable (U6-NFR-12, amending DR-13). It adds
  about a minute: each package's lookups give up after about 30 seconds, and the packages are looked up in parallel.

## Left to NFR Design (Minimal) and Infrastructure Design (Standard)

- **NFR Design** (settled, `../nfr-design/`): the patterns behind these targets. These include the two-phase smoke
  test, the scan gate and its accepted findings, building once and tagging last, and the writable paths under a
  read-only root.
- **Infrastructure Design** (settled, `../infrastructure-design/`):
  - the digests and commit SHAs;
  - Syft's registry, and how its binary and licence are copied;
  - the health probe's form (a mode of `Airlock.Web` or its own small program), its timeout, the intervals and the
    start period;
  - the staging root's path, and the writable mounts' paths and sizes;
  - how CI fetches, verifies and keeps current Grype, actionlint and zizmor;
  - the SBOM's format and Grype's settings;
  - pushing before tagging, and keeping the tested and pushed image the same;
  - CodeQL's build mode;
  - caching in CI (none in the release);
  - which test project holds the repository tests;
  - the coverage checker;
  - compose's behaviour when a pull fails before the first release.
