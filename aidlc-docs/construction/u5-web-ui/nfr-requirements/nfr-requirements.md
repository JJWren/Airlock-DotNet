# U5 Web UI — NFR Requirements

**Stage**: CONSTRUCTION — U5 Web UI — NFR Requirements (Standard depth)

Only what is specific to the Blazor UI. System-wide NFRs stay in `inception/requirements/requirements.md`; the API's
are U4's and still hold for the host; U5's functional design hands the values it left open to this stage. Values
marked "NFR Design" are chosen in the next stage within the bounds given.

| ID | Quality | Requirement | Check | Trace |
|---|---|---|---|---|
| U5-NFR-01 | Architecture | The UI lives in `Airlock.Web.Components` (layout, pages, shared components), `Airlock.Web.State` (`ScanSession`, one per circuit), `Airlock.Web.Interop` (`AirlockJs`) and `Airlock.Web.Theme`. Components and the session call the Application's use cases in-process; no UI type uses an Infrastructure type (rule 5) or an `HttpClient`: the server never calls its own API, and only the browser posts to it (ADR-0001). | Architecture rule 5, already enforced for every Web type; a new rule that no UI type depends on `HttpClient`; a positive control that a page reaches a use case | NFR-02; UR-41; ADR-0001 |
| U5-NFR-02 | Responsiveness | During a scan, a tab redraws for progress and log lines at most 4 times a second, coalescing bursts, and once a second for the timer; typing, clicks and keys are answered within 100 ms on the developer machine. Ten tabs following a scan of 1,000 packages lengthen it by no more than 5 % against the same scan with no tab open. | bUnit on a fake clock: a burst of 100 events within 250 ms causes at most two redraws; Build and Test measures the ten-tab scan | NFR-05; E08; UR-13 to UR-17 |
| U5-NFR-03 | Bounds per tab | The terminal keeps the last 1,000 lines, the size of a Live Log subscriber's buffer (U3), and Export Logs saves those. A tab holds one subscription each to the active slot, its scan and the Live Log, and at most one upload; all end with its session. A disconnected session is kept for Blazor's default of 3 minutes, at most 100 at once (`CircuitOptions`). | bUnit: 1,500 lines keep the last 1,000; disposing a session ends its subscriptions (a fake Live Log sees its subscriber leave; the Application's tests count the scan's subscribers) | FR-18; UR-03, UR-17; U4-NFR-09 |
| U5-NFR-04 | Large results | Reports stays usable with 2,000 inventory rows: drawn within 1 second, a filter's result within 300 ms of the last keystroke, a selection within 100 ms. | A smoke test asserts ten times these bounds on a generated scan, as U4's did; Build and Test measures them in the browser pane | NFR-05; UR-27 to UR-30 |
| U5-NFR-05 | Long uploads | A 2 GB upload over a slow link completes with its progress, however long it takes: no call from the server into the browser waits for the whole upload, since Blazor ends such a call after 1 minute (`JSInteropDefaultCallTimeout`). Progress arrives at least once and at most four times a second. The upload continues while the analyst changes pages; closing the tab ends it, and the server then frees the slot (U4-NFR-04). | bUnit: submitting returns at once and the answer arrives through the progress sink; Build and Test uploads 1 GiB through the browser pane, changing pages meanwhile | NFR-05; UR-10, UR-11; U4-NFR-04 |
| U5-NFR-06 | Connection loss | OFFLINE shows within 5 seconds when the server stops or closes the connection, and within 30 seconds — SignalR's default server timeout — when the network goes silent. Reconnection follows Blazor's defaults; a session the server no longer holds (the `rejected` state) is offered Reload. | Build and Test, in the browser pane: stop the server, see OFFLINE within 5 seconds; start it again, see Reload offered | E12; UR-05; ADR-0001 |
| U5-NFR-07 | Accessibility | The pages meet WCAG 2.2 AA (Q-U5-N1). **Contrast**: text at least 4.5:1, large text and the parts of controls at least 3:1, as measured in the table below. Small grey text uses #A1A1AA, while #71717A stays for borders, icons, dividers and disabled controls. Blue and red text on tinted or highlighted backgrounds uses #60A5FA and #F87171; fills, bars, dots and borders keep #3B82F6 and #EF4444. Text on a primary fill is dark (#09090B); placeholders meet 4.5:1. **Operation**: everything is reachable and usable by keyboard, with a visible focus and an order that follows the page; icon buttons have names; notices and snackbars are announced to screen readers; colour is never the only signal; reduced motion is honoured. | A test that computes the contrast of every text and background pair the theme uses; bUnit for names, roles and focusability; Build and Test: a keyboard pass and an axe-core scan of the three pages in the browser pane, with no serious or critical issue | NFR-12; E07; UR-35 to UR-38; Q-U5-N1 |
| U5-NFR-08 | Security | Pages load nothing from another host. Every page answer carries `X-Frame-Options: DENY` and a Content-Security-Policy with `frame-ancestors 'none'`, so another site cannot frame Airlock and steer a click onto Emergency Stop or Execute. The policy also allows scripts, styles, fonts, images and connections from Airlock itself only (`default-src 'self'`); the inline styles MudBlazor needs are the one allowance, which NFR Design settles. Pages also send `X-Content-Type-Options: nosniff`. External text — CVE descriptions, log messages, file names, reasons — is shown as text, never as markup. Blazor's antiforgery protects the UI's forms. The NVD key never reaches a page. | WebApplicationFactory: the headers on `/`, `/logs` and `/reports`; no other host in the markup; bUnit: a description holding `<script>` shows as text; Build and Test: the browser reports no CSP violation | NFR-03; UR-02, UR-36; ADR-0007 |
| U5-NFR-09 | Time and culture | Times are converted with the browser's IANA time zone on Windows and Linux, daylight saving included; the container image carries time-zone data (U6). Numbers and dates are formatted the same whatever the server's culture — "92.42", "9.8", ISO dates — and the text is English only. | Tests across the 2026-10-25 change from CEST to CET in `Europe/Berlin` and in `America/Phoenix`, which keeps no daylight saving; the same output under a `de-DE` current culture; CI on Windows and Linux (U6) | FR-31; UR-34 |
| U5-NFR-10 | Browsers | The current and previous major versions of Chrome, Edge, Firefox and Safari, with WebSockets, as Blazor requires. | Build and Test in Chromium, the browser pane; other browsers when available | NFR-01 |
| U5-NFR-11 | Page weight and start | A cold load of Control Center makes no request to another host, transfers less than 2 MB, and is interactive within 2 seconds on localhost. Static files are served compressed and fingerprinted, as .NET 10 does. | The browser pane's network log in Build and Test | NFR-05; UR-36; U4-NFR-07 |
| U5-NFR-12 | Observability | UI failures — an exception in a component, a failed call into the browser, a broken circuit — are logged at Error in `Airlock.Web` categories, without file contents or the key. Routine UI activity logs nothing at Information, so the Live Log shows scans, not clicks. | bUnit with a fake logger: a failing component logs one error; following a scan logs no UI line at Information | NFR-07; UR-39; U4-NFR-11 |
| U5-NFR-13 | Testability | Component tests run with the real Application over fakes of its ports, as U4's did; on a fake `TimeProvider`; with bUnit's JavaScript stand-in in strict mode, so that every call into `airlock.js` is planned; with MudBlazor's services registered as in the application. No test touches the network. `airlock.js` itself is checked by hand in the browser pane. | The suite passes offline; the manual checks of the U5 rule-to-test map | NFR-09; U4-NFR-13 |
| U5-NFR-14 | Coverage | Every rule UR-01 to UR-41 has its check in the rule-to-test map. `Airlock.Web` as a whole — API and UI, Razor components included, generated code excluded — keeps U4's targets of 90 % of lines and 85 % of branches. | Coverage report from `dotnet test`; enforced in CI from U6 | NFR-09; U4-NFR-14 |
| U5-NFR-15 | Maintainability | MudBlazor's components come first (ADR-0005); one theme class holds the tokens; one stylesheet holds what the theme cannot express — the terminal, the pulse, the fonts — besides scoped component styles; no CSS framework and no npm toolchain; `airlock.js` is a plain ES module without a bundler. Each component names its UR rules in a one-line comment; names follow GLOSSARY.md; warnings are errors. | Build; review at Code Generation | NFR-08; ADR-0005 |
| U5-NFR-16 | Licensing | MudBlazor (MIT); bUnit (MIT, tests only); Inter and JetBrains Mono (SIL Open Font License 1.1), whose licence texts ship beside the font files and which the README credits (U6). | The licence files in `wwwroot`; the README (U6) | NFR-10 |
